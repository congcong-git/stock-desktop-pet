**文档版本：** V1.0  
**产品类型：** Windows 桌面股票观察工具  
**文档状态：** 初版需求

---

## 1. 产品概述

### 1.1 产品定位

股票观察器是一款轻量级桌面股票行情观察工具，面向需要持续关注自选股及持仓股的用户。

产品核心目标：

- 快速搜索股票；
- 管理自选股和持仓股；
- 查看股票实时/准实时行情；
- 根据持仓情况计算今日盈亏；
- 通过背景颜色和动画直观反馈当前盈亏状态；
- 在交易关键时间点保存市场状态，并支持非交易时间恢复最近状态。

### 1.2 产品核心价值

通过一个常驻桌面的轻量化窗口，让用户无需频繁打开完整行情软件，即可快速了解：

> “我关注的股票现在怎么样，我今天到底赚了还是亏了。”

# 5. 功能需求

## 5.1 股票搜索

### 5.1.1 功能描述

用户可以通过股票名称或股票代码搜索股票。

搜索框支持模糊匹配。

### 5.1.2 股票名称搜索

例如用户输入：

```text
中科
```

系统返回股票名称包含“中科”的股票。

示例：

```text
中科曙光
中科信息
中科创达
中科江南
```

### 5.1.3 股票代码搜索

例如用户输入：

```text
688
```

系统返回股票代码中包含“688”的股票。

### 5.1.4 自动检索

用户输入内容后，系统自动执行搜索。

建议增加约300~500ms输入防抖，避免用户每输入一个字符都发起一次请求。

### 5.1.5 搜索结果

搜索结果以列表形式展示。

字段：

| 字段 | 说明 |
|---|---|
| 序号 | 搜索结果序号 |
| 股票名称 | 股票名称 |
| 股票代码 | 股票代码 |
| 操作 | 加入自选、加入持仓 |

默认优先展示10条结果。

当搜索结果超过当前显示区域时，支持滚动查看。

### 5.1.6 搜索结果操作

每条股票提供：

```text
[加入自选]
[加入持仓]
```

点击“加入自选”：

- 股票加入自选股列表；
- 如果已经存在，则不重复添加；
- 提示用户添加成功。

点击“加入持仓”：

- 股票加入持仓股列表；
- 如果已经存在，则不重复添加；
- 如果需要持仓数量等信息，则进入持仓信息录入流程。

# 6. 自选股

## 6.1 功能描述

自选股用于保存用户长期关注但不一定持有的股票。

## 6.2 自选股列表

使用表格展示。

### 表头

```text
序号 | 股票名称 | 当前涨幅 | 较开盘价涨跌幅
```

### 示例

| 序号 | 股票名称 | 当前涨幅 | 较开盘价涨跌幅 |
|---:|---|---:|---:|
| 1 | 中科曙光 | +3.25% | +1.82% |
| 2 | 中兴通讯 | -1.32% | -0.52% |

## 6.3 行情字段

### 当前涨幅

计算公式：

```text
当前涨幅 =
(当前价格 - 昨日收盘价) / 昨日收盘价 × 100%
```

### 较开盘价涨跌幅

计算公式：

```text
较开盘价涨跌幅 =
(当前价格 - 今日开盘价) / 今日开盘价 × 100%
```

## 6.4 颜色规则

股票上涨：

```text
红色
```

股票下跌：

```text
绿色
```

股票持平：

```text
黑色/默认颜色
```

### 示例

# 8. 持仓信息

每一只持仓股票至少需要保存：

| 字段 | 必填 | 说明 |
|---|---|---|
| 股票代码 | 是 | 股票唯一标识 |
| 股票名称 | 是 | 股票名称 |
| 持股数量 | 是 | 当前持有数量 |
| 持仓成本价 | 建议 | 股票持仓成本 |
| 添加时间 | 否 | 记录加入时间 |

> V1.0如果只计算“今日盈亏”，核心计算依赖昨日收盘价和持股数量；持仓成本价可作为后续扩展字段保留。

# 9. 今日盈亏

## 9.1 功能描述

系统根据用户持仓股票的当前价格、昨日收盘价以及持股数量，计算今日盈亏。

## 9.2 单只股票今日盈亏

公式：

```text
单只股票今日盈亏 =
(当前价格 - 昨日收盘价) × 持股数量
```

例如：

```text
昨日收盘价：20元
当前价格：21元
持股数量：1000股

今日盈亏：
(21 - 20) × 1000
= +1000元
```

## 9.3 总今日盈亏

```text
今日总盈亏 =
股票A今日盈亏
+ 股票B今日盈亏
+ 股票C今日盈亏
+ ...
```

底部固定展示：

```text
今日盈亏：+1,286.50 元
```

---

# 10. 盈亏状态

根据今日总盈亏确定系统当前状态。

| 条件 | 状态 | 背景 |
|---|---|---|
| 今日盈亏 > 0 | 盈利 | 红色 |
| 今日盈亏 < 0 | 亏损 | 绿色 |
| 今日盈亏 = 0 | 持平 | 黑色 |

状态发生变化时，界面实时更新。

# 11. 牛熊动画

## 11.1 功能描述

界面右侧/侧边设置动画展示区域。

系统提供两个动画：

- 牛动画；
- 熊动画。

## 11.2 牛动画

当本次计算得到的今日总盈亏高于上一次计算结果时，播放牛动画。

判断：

```text
当前总盈亏 > 上一次总盈亏
```

示例：

```text
上一次：+500元
本次：+800元

800 > 500

播放牛动画
```

## 11.3 熊动画

当本次计算得到的今日总盈亏低于上一次计算结果时，播放熊动画。

判断：

```text
当前总盈亏 < 上一次总盈亏
```

示例：

```text
上一次：+800元
本次：+300元

300 < 800

播放熊动画
```

## 11.4 持平

如果：

```text
当前总盈亏 = 上一次总盈亏
```

则不播放新的动画。

# 12. 行情刷新

## 12.1 刷新频率

程序启动后立即执行一次行情刷新。

之后每10秒刷新一次。

刷新时间建议对齐到整10秒：

```text
00秒
10秒
20秒
30秒
40秒
50秒
```

而不是简单按照“启动后每10秒”计算。

## 12.2 刷新内容

每次刷新至少更新：

- 当前价格；
- 当前涨幅；
- 较开盘价涨跌幅；
- 单只股票今日盈亏；
- 今日总盈亏；
- 盈亏背景；
- 牛/熊动画状态。

## 12.3 批量行情

如果行情接口支持批量查询，应一次性获取所有自选股及持仓股行情，减少网络请求。

# 15. 非交易时间状态恢复

## 15.1 功能描述

当用户在非交易时间打开程序时，由于市场没有实时交易数据，系统读取本地保存的最近一次状态。

## 15.2 场景

### 午间休市

例如：

```text
11:30
```

保存上午状态。

用户：

```text
12:00
```

启动软件。

系统读取：

```text
11:30状态
```

### 收盘后

例如：

```text
15:00
```

保存最终状态。

用户：

```text
20:00
```

启动软件。

系统读取：

```text
15:00状态
```

### 第二天开盘前

如果当天尚未产生新的状态：

```text
读取最近一个已完成交易日15:00状态
```

# 18. 异常处理

## 18.1 行情接口异常

行情请求失败时：

- 不清空当前已显示的数据；
- 保留上一次有效行情；
- 提示行情更新失败；
- 下一次10秒周期继续尝试。

## 18.2 单只股票行情失败

如果某一只股票获取行情失败：

- 其他股票正常更新；
- 该股票显示“行情获取失败”；
- 不影响整体盈亏计算，或者按照产品最终确定的规则处理。

建议V1.0采用：

> 行情缺失股票不参与本次盈亏计算，并标记数据异常。

## 18.3 本地数据读取失败

如果本地JSON损坏：

- 尝试备份文件恢复；
- 无法恢复时提示用户；
- 不影响软件启动。

## 18.4 网络断开

网络断开时：

- 显示“网络异常”；
- 保留最后一次有效行情；
- 不播放新的牛熊动画；
- 恢复网络后自动继续刷新。

# 19. 数据一致性规则

需要保证：

### 自选股不能重复

同一个股票代码只能存在一次。

### 持仓股不能重复

同一个股票代码只能存在一条持仓记录。

### 自选和持仓可以同时存在

例如：

```text
中科曙光
```

可以同时存在于：

```text
自选股
持仓股
```

两者互不影响。

---

# 20. 性能要求

V1.0属于轻量级桌面应用，性能要求不高。

目标：

- 程序启动时间尽可能控制在2秒级；
- 行情刷新过程不能阻塞UI；
- 网络请求采用异步方式；
- 连续运行过程中不能因为10秒定时器造成资源持续增长；
- 动画播放不能明显影响行情刷新。

# 23. 待产品确认事项

以下内容建议在正式开发前确定：

### 23.1 行情数据源

需要确定具体股票行情接口，以及：

- 实时性；
- 免费额度；
- 调用频率；
- 批量查询能力；
- 是否需要Token；
- 是否允许商业/个人使用。

### 23.2 “今日盈亏”定义

本PRD暂定：

```text
今日盈亏 =
(当前价格 - 昨日收盘价) × 持股数量
```

即只反映“今天相对于昨日收盘”的盈亏。

### 23.3 持仓成本价

虽然当前今日盈亏计算不依赖成本价，但建议保存，为未来增加：

- 总浮盈亏；
- 收益率；
- 持仓成本；
- 盈亏比例；

等功能预留数据基础。

### 23.4 交易日历

正式版本建议接入A股交易日历，不能简单通过“周一至周五”判断交易日，因为A股存在节假日及调休情况。

# 24. V1.0验收标准

产品完成后，至少满足以下验收条件：

### 搜索

- 输入股票名称可以搜索；
- 输入股票代码可以搜索；
- 搜索结果自动更新；
- 搜索结果超过10条可以滚动；
- 可以将股票加入自选；

## 产品核心原则

V1.0不追求做成一个“大而全”的股票软件，而是坚持：

> **小、快、直观。**

打开软件后，用户应该在几秒内知道三件事：

**我关注的股票现在涨跌多少 → 我的持仓今天赚了还是亏了 → 当前市场状态是在变好还是变坏。**

# 26. 开发确认与实现约束

以下内容为本次开发前确认结果，用于指导 V1.0 实现落地。

## 26.1 技术栈确认

- 桌面端采用 `Electron + React` 实现；
- 目标交付物为 Windows 可执行程序 `.exe`；
- 本轮交付目标为：
  - 可运行；
  - 可打包；
  - 覆盖 PRD 中的 V1.0 核心流程。

## 26.2 数据源策略确认

- V1.0 优先采用免费公开的 A 股行情接口；
- 搜索与行情能力优先满足：
  - 股票名称/代码模糊搜索；
  - 批量行情获取；
  - 当前价、昨收、今开等字段读取；
- 如公开接口存在限流、字段缺失或临时不可用情况，允许在实现中增加降级与兜底策略。

## 26.3 V1.0 交付边界

本次开发以可用版本为目标，优先实现以下闭环：

- 股票搜索；
- 加入自选；
- 加入持仓；
- 本地 JSON 持久化；
- 行情刷新；
- 今日盈亏计算；
- 盈亏背景状态切换；
- 牛/熊动画状态反馈；
- 11:30 / 15:00 状态保存；
- 非交易时间最近状态恢复；
- Windows `.exe` 打包能力。

## 26.4 实现约束

- 本地数据继续采用 JSON 文件存储，不引入数据库；
- 界面优先保证“小、快、直观”，不过度增加复杂交互；
- 行情接口异常时保留最后一次有效数据；
- 单只股票行情缺失时，该股票不参与本次盈亏计算；
- 打包配置需支持在 Windows 环境生成安装产物；
- 若运行环境依赖版本限制导致部分工具链无法使用，可在不改变产品目标的前提下选择兼容实现方案。
