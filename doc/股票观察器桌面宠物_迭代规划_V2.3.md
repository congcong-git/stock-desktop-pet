# 股票观察器（牛来）桌面宠物 · 迭代规划 V2.3+

> **文档定位**：记录 V2.2 之后的迭代规划，按批次推进。每个批次结束发一版（GitHub Actions 自动打包并发布 Release）。
>
> **产品判断**：当前形态是"会动的行情指示器"，还不是完整的"宠物"。行情能力（V1.0）已较完整，V2.x 补的是外观与工具链；下一阶段要解决的是**陪伴感缺失**、**已存数据未被利用**、**个性化能力不足**三件事。
>
> **使用场景**：自用 + 分享给身边人。因此"开机自启 / 自动更新 / 首次引导"属于分享的前置条件，优先级高于纯功能迭代。

---

## 0. 推进原则

1. **一次一条线**：不并行开工，避免三条线同时铺开导致每条都做不深。
2. **每批一个可感知增量**：批次结束必须能明确说出"这次多了什么"。
3. **每批发版**：P0 完成后，后续迭代通过自动更新送达使用者，不再手工分发安装包。
4. **先低成本高感知**：优先做"数据已存在、只差呈现"的需求（如历史盈亏曲线）。

## 2. P0 · 分享前置

### 2.1 开机自启

| 项 | 规则 |
|---|---|
| 入口 | 右键菜单「设置」→「开机自启」；托盘菜单同步提供开关 |
| 实现 | `app.setLoginItemSettings({ openAtLogin })`，仅对安装版生效（开发模式跳过） |
| 持久化 | 开关状态写入本地配置（`Data/app-config.json` 或沿用现有配置机制） |
| 默认 | 安装后**默认关闭**，首次引导中主动询问一次 |
| 约束 | 打包版与开发版的 `userData` 目录不同，配置不共享 |

### 2.2 自动更新

| 项 | 规则 |
|---|---|
| 方案 | 接入 `electron-updater`，复用现有 GitHub Releases（package.json 已配 `publish.provider = github`） |
| 触发 | 启动后静默检查；发现新版本弹窗提示，用户确认后下载安装 |
| 静默策略 | 默认**提示后更新**，不强制；可在设置中关闭检查 |
| 版本来源 | `package.json` 的 `version`，发版前需 `npm version patch/minor` 递增 |
| 前置 | 确认 GitHub Release 为公开可访问；私有仓库需额外处理令牌 |
| 回退 | 更新失败不影响当前版本运行，下次启动重试 |

> 不做自动更新时，每次迭代都需要对方手动下载覆盖安装，分享人数变多后维护成本会快速上升。

### 2.3 首次启动引导

| 项 | 规则 |
|---|---|
| 触发 | 首次运行（本地无引导标记）时展示，之后不再出现 |
| 内容 | ① 右键宠物能看到什么 ② 素材库在哪、可以换形象 ③ 托盘图标的作用（最小化后找回） |
| 形态 | 气泡 / 轻量浮层，可跳过；面板内提供「重新查看引导」入口 |

### P0 验收要点

1. 开启自启后重启系统，宠物自动出现；
2. 发布新版本后，旧版本启动能收到更新提示并成功升级；
3. 首次启动有引导，关闭后不再重复弹出。

## 3. M8 · 数据深度一期

> 目标：从"今天赚了多少"升级到"这段时间赚了多少、赚得稳不稳"。

### 3.1 累计浮盈与收益率

现状：`holdings.json` 已存 `costPrice`，但面板只计算**今日盈亏**（依赖昨日收盘价），从未展示累计维度。

| 项 | 规则 |
|---|---|
| 单只浮盈 | `(当前价 - 成本价) × 持股数`；无成本价时显示 `--`，不计入汇总 |
| 持仓总成本 | `Σ(成本价 × 持股数)`（仅统计有成本价的持仓） |
| 持仓总市值 | `Σ(当前价 × 持股数)` |
| 累计浮盈 | `总市值 - 总成本` |
| 收益率 | `累计浮盈 ÷ 总成本 × 100%`；总成本为 0 时显示 `--` |
| 展示 | 面板摘要区新增一行；底部胶囊新增「累计浮盈」显示项（与今日盈亏并列可选） |
| 颜色 | 沿用涨红跌绿规则，持平为默认色 |

### 3.2 近 30 天盈亏曲线

现状：`daily-history.json` 已滚动保存最近 30 个交易日的 11:30 / 15:00 快照，数据基础完备但从未可视化。

| 项 | 规则 |
|---|---|
| 数据源 | `Data/daily-history.json`，每个交易日取 15:00 快照（缺失时回退 11:30） |
| 图表 | 每日盈亏柱状图（正红负绿）+ 累计盈亏折线（次轴或同轴的累计值） |
| 交互 | 悬停显示日期、当日盈亏、累计值；横轴按交易日排列（跳过休市日） |
| 空态 | 无任何历史数据时给出说明文案（"交易 1 天后即可看到曲线"） |
| 展示位置 | 管理面板新增「历史盈亏」卡片；宠物侧暂不展示 |

### 3.3 摘要区改造

- 今日盈亏 / 累计浮盈 / 总市值 / 收益率 分区清晰，避免信息堆叠；
- 保持现有"盈利红 / 亏损绿"的背景反馈与 0.6 秒渐变。

### M8 验收要点

1. 录入成本价后，累计浮盈与收益率数值正确（含无成本价持仓被正确排除）；
2. 历史曲线能读出近 30 个交易日数据，休市日不出现空洞；
3. 无历史数据时显示空态说明，不报错；
4. 胶囊新增的「累计浮盈」显示项可切换且重启后保持。

## 4. M9 · 陪伴感与提醒

> 目标：让宠物"有反应"，并把桌宠常驻的优势用在提醒上。

### 4.1 点击反馈

| 项 | 规则 |
|---|---|
| 单击宠物 | 播放一次反馈动画（摸头 / 摇尾巴），并冒出气泡 |
| 气泡内容 | 优先行情相关（当日盈亏、最强/最弱持仓），无行情时随机台词 |
| 与拖动兼容 | 拖动（按住移动）不触发点击反馈，需区分 click 与 drag |
| 气泡时长 | 约 3 秒后淡出，再次点击可立即换一句 |

### 4.2 非交易时段状态

| 场景 | 宠物状态 |
|---|---|
| 开盘前 | 待机（可考虑"伸懒腰"） |
| 交易中 | 现有盈亏联动 |
| 午间休市 | "休息"状态 |
| 收盘后 | "打盹"状态，气泡可给收盘小结 |
| 周末 / 节假日 | "睡觉"状态 |

- 状态切换不影响底部胶囊的快照展示逻辑（沿用 V1.0 快照恢复规则）；
- 可在设置中关闭"非交易时段状态"，保持常驻同一表情。

### 4.3 异动提醒

| 项 | 规则 |
|---|---|
| 提醒项 | ① 单只自选/持仓涨跌幅超阈值 ② 当日总盈亏突破金额阈值 |
| 默认阈值 | 单只 ±3%；总盈亏 ±1000 元（可在面板设置中调整） |
| 形态 | 气泡 + 系统通知（Electron `Notification`） |
| 去重 | 同一只股票同一方向在 N 分钟内不重复提醒（建议 10 分钟） |
| 免打扰 | 非交易时段不提醒；可整体关闭 |
| 权限 | 首次提醒前如系统禁用通知，给出一次说明提示 |

### 4.4 收盘小结

- 15:00 快照保存后，宠物气泡播报一次当日总结（总盈亏、最强/最弱持仓）；
- 当天只播报一次，可关闭。

### 4.5 节日彩蛋（可选）

- 元旦 / 春节 / 生日等触发专属表情或气泡文案；
- 数据放在本地配置，不依赖网络。

### M9 验收要点

1. 单击宠物有动画与气泡，拖动时不会误触发；
2. 非交易时段宠物进入对应状态，且不影响快照显示；
3. 异动达到阈值时气泡与系统通知均出现，同方向不重复轰炸；
4. 收盘小结每天只出现一次。

### 4.6 实现说明（落地要点）

**配置存储**：`app-config.json` 新增 `companion` 段（主进程为唯一数据源，改动通过 `app:config-changed` 广播到宠物窗口）：

```json
{
  "companion": {
    "tapFeedback": true,
    "idleState": true,
    "alertsEnabled": true,
    "stockPercent": 3,
    "profitAmount": 1000,
    "cooldownMinutes": 10,
    "dailySummary": true
  }
}
```

- 读取与写入走 `getCompanionConfig()` / `setCompanionConfig()`，旧配置缺字段自动补默认值，越界值收敛到合法区间（涨跌幅 0.5–20%、金额 100–100 万、间隔 1–120 分钟）。
- 设置入口：宠物右键 →「设置」→「陪伴与提醒」（阈值与间隔用预设档位单选，避免弹输入框）。

**点击反馈的技术前提**：宠物窗口整窗是 `-webkit-app-region: drag`，drag region 会吞掉渲染层的左键事件，点击反馈收不到。曾尝试改为渲染层手动拖动（渲染层算位移、主进程 `setPosition` 移动），但 Windows 上透明窗口被主进程高频移动时 DWM 透明会失效，拖动时整窗变成黑块。最终方案：

- 拖动保留系统 drag region（跟手、不破坏透明）；
- 单击检测由主进程 `hookWindowMessage` 监听 `WM_LBUTTONDOWN` / `WM_LBUTTONUP` 原生消息：按下-抬起位移 ≤ 8px 且时长 ≤ 800ms 判定为单击，发 `pet:tapped` 给宠物窗口播放摸头 / 摇尾巴动画（仅 Windows；本项目只支持 Windows）。

**异动检测位置**：放在宠物渲染层每轮 `refreshMarket()` 之后（宠物常驻，面板可能关闭），命中后气泡 + `notify:alert` 让主进程发系统通知。

- 去重：`alertMemoryRef` 内存态，键为 `股票代码:方向`，重启后重置（可接受，避免开机提醒旧数据）；
- 免打扰：仅在「上午交易 / 下午交易」时段检测，且首轮（冷启动恢复的快照数据）不触发；
- 降级：`Notification.isSupported()` 为 false 时只保留气泡，并提示一次。

**收盘小结**：`refreshMarket()` 返回的 `snapshotTime === "15:00"` 时触发，播报日期写入 localStorage（`pet.summaryDate`），当天不再重复。

## 5. M10 · 外观个性化

### 5.1 宠物显示设置

| 项 | 规则 |
|---|---|
| 缩放 | 支持 50% – 200%（建议档位或滑杆），窗口尺寸与素材等比缩放 |
| 透明度 | 非激活时透明度可调（如 30% – 100%），鼠标移入恢复 |
| 鼠标穿透 | 开启后鼠标事件穿透宠物（不挡操作）；**默认关闭**，可用快捷键临时切换 |
| 贴边隐藏 | 靠屏幕边缘时自动收起（可选，体验优化项） |
| 持久化 | 上述设置写入本地配置，重启保持 |

### 5.2 素材微调

- 单个情绪素材支持：缩放、上下左右偏移、左右翻转；
- 调整结果随绑定一起持久化（扩展 `mood-bindings.json` 结构，需兼容旧数据）；
- 素材库面板提供可视化微调（拖动 / 滑杆）。

### 5.3 内置素材包与"上传照片做宠物"

- 内置 2 – 3 套形象（**仅使用 AI 生成或自绘素材，规避版权风险**）；
- 首次进入素材库时引导"上传一张照片 → 去背景 → 设为宠物"，复用已实现的去背景能力；
- 一键恢复默认形象。

### M10 验收要点

1. 缩放、透明度、穿透三项设置即时生效且重启保持；
2. 素材微调结果随绑定保存，旧数据升级后不丢失绑定；
3. 内置素材可一键切换，恢复默认形象正常。

## 9. 发版与自动更新流程

> 本章说明 **CI 什么时候打包 / 什么时候发布**，以及发版的具体操作步骤。
> 目标：日常提交不打扰使用者，只有明确发版才产生可更新的 Release。

### 9.1 CI 触发规则

| 触发方式 | 触发的流水线 | 行为 | 是否发布 |
|---|---|---|---|
| push 到 `main` | `build-release.yml`（build-check） | 构建 Windows 安装包，上传 Actions artifact | 否 |
| push tag `v*`（如 `v1.0.5`） | `release.yml` | 构建 **Windows + macOS** 双平台并发布（含 `latest.yml` / `latest-mac.yml`） | 是 |
| 手动 `workflow_dispatch` | 任选一条 | `build-check` 只构建；`Release` 会双平台构建并发布 | 视所选流水线 |
| 仅改动 `doc/**` 或 `*.md` | — | 不触发 build-check；不影响打 tag 发版 | — |

两条流水线分工明确：`release.yml` 负责正式发版（打 tag 即双平台构建 + 发布），`build-release.yml` 只做日常构建校验。这样做是为了避免打 tag 时两条流水线同时运行、争抢同一个 Release 导致上传冲突（中文文件名在 GitHub 上传会报 `unescaped characters`）。

### 9.2 发版操作步骤

```bash
# 1. 确认工作区干净（无未提交改动）
git status

# 2. 升版本号并自动打 tag
npm version patch      # 修 bug / 小改动：1.0.4 → 1.0.5
# npm version minor    # 完成一条功能线：1.0.5 → 1.1.0

# 3. 连同 tag 一起推送，触发打包并发布
git push --follow-tags
```

`npm version` 会自动完成三件事：修改 `package.json` 的 `version` → 生成一条 commit → 打同名 tag（如 `v1.0.5`）。

发布完成后，在仓库 **Releases** 页面确认三样东西都在：Windows 安装包（`niulai-setup-*.exe`）、macOS 包（`niulai-*-mac-*.dmg` / `.zip`）、更新元数据（`latest.yml` 与 `latest-mac.yml`）。

### 9.3 版本号策略

| 变更类型 | 命令 | 示例 |
|---|---|---|
| 修 bug / 文案 / 小调整 | `npm version patch` | 1.0.4 → 1.0.5 |
| 完成一条功能线（M8 / M9 / M10） | `npm version minor` | 1.0.5 → 1.1.0 |
| 架构级变更 | `npm version major` | 1.x.x → 2.0.0 |

> **不升版本号就发版 = 白发**。自动更新靠"远端版本 > 本地版本"判断是否提示，版本相同时使用者不会收到任何更新提示。

### 9.4 自动更新（P0 已落地，自 v1.0.5 起）

| 项 | 规则 |
|---|---|
| 检测源 | Release 中的 `latest.yml`（Windows）与 `latest-mac.yml`（macOS） |
| 触发条件 | 远端版本 **大于** 本地版本 |
| 检查时机 | 启动 5 秒后检查一次 + 每 4 小时复查 |
| 下载策略 | 默认 `autoDownload = false`：发现新版本先弹窗询问，用户确认后再下载 |
| 安装 | 下载完成后询问「立即重启安装」或「下次启动时安装」 |
| 免打扰 | 更新失败不影响当前版本运行，下轮检查自动重试 |
| 生效环境 | 仅**安装版**生效；`npm start` 开发模式会提示「开发模式不支持检查更新」 |
| 手动检查 | 托盘菜单与宠物右键菜单「设置」→「检查更新…」 |
| 私有仓库 | 需处理访问令牌；**公开仓库零配置** |

### 9.5 常见问题

**Q：我推了代码，为什么使用者没收到更新提示？**

版本号没变。按 9.2 执行 `npm version patch` 后再推送。

**Q：只想自测，不想发布给使用者？**

直接 push 到 `main`，到 Actions 页面下载构建产物（artifact `niulai-setup-<编号>`）即可。

**Q：这次发版只改了文档，没有代码改动？**

`doc/**` 与 `*.md` 不会触发 build-check。只改文档无需发版；要发布必须改代码 + 升版本 + 打 tag。

**Q：发布失败，提示资产已存在 / 需要重发？**

通常是版本号重复（Release `v1.0.5` 已存在，含 draft）。先清理再重发：
1. `git push origin --delete v1.0.5`（删远端 tag）
2. `gh release delete v1.0.5 --yes`（删 Release，draft 也会一并删；没装 gh 就去网页 Releases 页删）
3. `git tag -d v1.0.5`（删本地 tag）
4. 重新 `git tag v1.0.5 && git push origin v1.0.5`

**Q：发版一次要多久？产物有哪些？**

约 10–15 分钟（macOS 构建较慢）。Release 含 Windows 安装包 `niulai-setup-<版本>.exe`、macOS `.dmg` / `.zip`（x64 与 arm64），以及 `latest.yml` / `latest-mac.yml`。

**Q：使用者一直不更新，会不会有问题？**

不会。自动更新失败或跳过都不影响当前版本运行；但旧版本不会收到新功能，建议发版后在群里同步一句版本号。
