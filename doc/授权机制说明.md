# 牛来桌宠 · 授权机制说明

本软件采用**离线授权**：首次打开必须激活才能使用。不需要服务器，也没有联网校验。

---

## 1. 机制概览

| 项 | 设计 |
|---|---|
| 算法 | **Ed25519 非对称签名**（应用内置公钥，私钥只在你本机） |
| 绑定 | 激活码**绑定机器指纹**，拷到别的机器立即失效 |
| 有效期 | 永久有效（`exp: null`） |
| 台数限制 | 同一份授权最多 **3 台**，由签发台账控制 |
| 未激活行为 | 只显示激活窗口，**不创建宠物窗口、不刷新任何行情数据** |
| 校验位置 | 全部在**主进程**，改渲染层 JS 拿不到数据 |

因为应用只内置公钥，别人拿到代码也**无法伪造激活码**。

---

## 2. 用户侧流程

1. 首次启动弹出「牛来 · 授权激活」窗口，显示**本机机器码**（如 `8A8C-1D19-50A7-D05E`）；
2. 点「复制」把机器码发给作者；
3. 作者签发后，用户粘贴**激活码** → 点「激活并使用」；
4. 激活成功后窗口自动关闭，进入桌面宠物。

查看当前授权：**右键宠物 → 授权信息…**（归属方 / 机器码 / 激活时间 / 有效期）。

## 3. 作者侧签发

### 3.1 可视化工具（推荐）

**最省事的方式：双击项目根目录的 `授权签发工具.bat`**（可在桌面建快捷方式）。

它会自动完成：首次使用先构建界面 → 之后直接用本地 Electron 启动（跳过构建，秒开），无需打开 IDE 或敲命令。

备用启动命令：

```bash
npm run license-admin
```

> 更便捷的两种演进方案（独立 EXE / 集成进主程序）见本文 **第 10 节**，按需再做。

会打开一个独立的「授权签发工具」窗口：

| 区域 | 功能 |
|---|---|
| 顶部 | 名额占用（如 `1/3`） |
| 左侧 | 填**机器码** + **归属** → 点「签发激活码」→ 生成激活码，点「复制」发给用户 |
| 右侧 | 已签发机器列表，可随时「复制激活码」或「解绑」 |
| 提示 | 私钥缺失时提供一键生成；解绑有二次确认 |

- **中文归属可直接在界面里输入**（走 IPC，不受 Windows 控制台编码影响，不会出现乱码）；
- 该窗口是独立入口，`package.json` 的打包清单只含 `dist` / `electron` / `package.json`，
  所以工具**不会出现在用户安装包里**。

### 3.2 命令行（备用）

工具不参与打包，只在你的本机运行。

```bash
# 1）生成密钥对，只需做一次
node tools/gen-license.js keygen

# 2）签发激活码（machieId 换成用户发来的机器码）
node tools/gen-license.js issue --machine=8A8C-1D19-50A7-D05E --owner=张三

# 中文归属建议用文件方式（PowerShell 直接传中文参数可能变乱码）
node tools/gen-license.js issue --machine=8A8C-1D19-50A7-D05E --owner-file=owner.txt

# 3）查看已签发机器与名额占用
node tools/gen-license.js list

# 4）用户换机器：解绑旧的，释放名额
node tools/gen-license.js revoke --machine=8A8C-1D19-50A7-D05E
```

- 名额满时 `issue` 会直接拒绝，提示先 `revoke`；
- 同一台机器重复签发会覆盖记录，**不额外占用名额**；
- `--owner-file` 指向的文件请以 **UTF-8** 保存。

## 4. 激活码结构

```
激活码 = Base32(payload) + "." + Base32(签名)
payload = { v, mid（机器码）, owner, iat（签发时间）, exp（null=永久） }
```

- 用 **Base32**（字母表 `A-Z` + `2-7`）而非 Base64：不含易混字符 `0/1/8/9`，也不含 `-`，
  所以激活码里可以放心用 `-` 做抄写分隔；
- `normalizeCode` 会剔除空白、分隔线与全角横线后再解析，粘贴时多复制空格也没关系；
- Ed25519 签名仅 64 字节，整串激活码约 280 字符。

---

## 5. 机器指纹如何生成

主板序列号 + CPU ID + 系统 UUID + 系统盘序列号 + 主机名 → SHA-256 → 取前 16 位 → 分组。

- 厂商常见占位值（`To be filled by O.E.M.`、`Default string`、全 0 UUID 等）会被过滤；
- 任一项取不到都有降级，**保证任何机器都能算出一个稳定机器码**，不会把用户卡死；
- 结果缓存在内存中，不会重复调用 PowerShell。

## 6. 存储位置

| 文件 | 位置 | 说明 |
|---|---|---|
| 授权文件 | `%APPDATA%/牛来/license.dat` | 含激活码与机器码，重装软件不影响 |
| 私钥 | `keys/private.pem` | **务必备份**，丢失则无法再签发 |
| 公钥 | `keys/public.pem` + 已写入 `electron/license.js` | 公开无风险 |
| 签发台账 | `keys/licenses.json` | 记录已签发机器与名额 |

`keys/` 已在 `.gitignore` 中忽略，**不会进入仓库**。

## 7. 运行期校验点（加固）

| 时机 | 行为 |
|---|---|
| 启动 | 未授权 → 只弹激活窗口，不创建宠物、不启动定时任务 |
| 行情刷新 `market:refresh` | 未授权直接返回 `null`，改渲染层也拿不到行情 |
| 每 30 分钟 | 复核一次，一旦失效：关闭宠物/面板/素材库并回到激活窗口 |
| 菜单「授权信息…」 | 实时显示授权状态 |

## 8. 已知边界（必须知道）

Electron 是客户端应用，**本地校验在理论上都能被 patch**（反编译后改掉判定）。
当前方案保证的是：

- 无法伪造激活码（非对称签名，只有你有私钥）；
- 无法把授权复制到别的机器（机器指纹绑定）；
- 单纯改前端 JS 无法使用（数据与能力都在主进程）。

若后续需要更强保护，可再叠加：主进程代码混淆（`javascript-obfuscator`）/ 字节码编译（`bytenode`）、
多处交叉校验、asar 完整性检查。按需再做，不必一开始投入。

## 9. 常见问题

| 问题 | 处理 |
|---|---|
| 换电脑 | 新机器的机器码发给作者重新签发，并建议解绑旧机器 |
| 重装系统 | 同一台机器通常指纹不变，用原激活码重新激活即可 |
| 提示「激活码与本机不匹配」 | 激活码是别的机器的，需按本机机器码重新签发 |
| 提示「签名校验未通过」 | 激活码被截断或改动，请重新完整复制 |
| 名额已满 | 作者执行 `revoke` 解绑一台旧机器后再签 |
| 私钥丢失 | 只能重新 `keygen --force`，代价是已签发的激活码全部失效 |

## 10. 后续可选：更便捷的签发入口（未实现，备查）

当前采用 **双击 `授权签发工具.bat`**（依赖项目目录与 `node_modules`）。
若将来希望"脱离开发环境"或"不用去源码目录"，有以下两种演进方案，实现要点记录备查。

### 10.1 方案 B：打包成独立 EXE

**目标**：产出 `授权签发工具.exe`，双击即用，不依赖 Node / 源码，可拷贝到任意电脑。

**实现步骤**

1. 新建独立打包配置 `tools/license-admin-builder.json`：

```json
{
  "appId": "com.trae.stockwatcher.licenseadmin",
  "productName": "牛来授权签发工具",
  "directories": { "output": "release" },
  "files": [
    "dist/license-admin.html",
    "dist/license-admin.js",
    "dist/license-admin.css",
    "tools/license-admin.js",
    "tools/license-admin-preload.js",
    "tools/license-store.js"
  ],
  "win": { "target": ["portable"] },
  "portable": { "artifactName": "授权签发工具.${ext}" }
}
```

2. 在 `package.json` 增加脚本：

```json
"dist:license-admin": "npm run build:renderer && electron-builder --win portable --config tools/license-admin-builder.json"
```

3. **私钥处理（关键点）**：打包时**不要**把 `keys/` 打进去。运行时按以下顺序找私钥：

   - exe 同级目录 `keys/private.pem`（用户把 keys 文件夹拷到 exe 旁边）
   - 用户通过界面「选择私钥文件…」指定（`dialog.showOpenDialog`）

   对应改动：`tools/license-store.js` 的 `keysDir` 改为可配置，增加 `setKeysDir(dir)`；
   界面在缺少私钥时提供「选择私钥」按钮。

4. 产物约 80MB（含 Electron 运行时）；界面每次修改后需重新执行 `npm run dist:license-admin`。

**注意**：`tools/license-store.js` 与 `tools/license-admin*.js` 会被打进这个独立 EXE，但它们**不在主程序打包清单**（`package.json build.files`）里，所以用户安装包不受影响。

---

### 10.2 方案 C：集成进主程序

**目标**：在本机已安装的牛来桌宠里直接唤起签发窗口（托盘菜单 / 快捷键），不用去源码目录。

**实现步骤**

1. **迁移签发逻辑**：把 `tools/license-store.js` 移到 `electron/license-store.js`（`tools/gen-license.js` 与可视化工具同步改为引用新路径）。
   - 代价：签发能力会进入用户安装包；但用户机器上没有私钥，功能天然不可用，风险可控。

2. **私钥位置**：`license-store.js` 支持按优先级查找私钥：

   - `app.getPath("userData")/license-tools/private.pem`（作者把自己的私钥放一次）
   - 开发模式下项目根目录 `keys/private.pem`
   - 界面里「选择私钥文件…」手动指定

3. **入口**：

   - 托盘菜单增加「授权签发工具…」（仅检测到私钥时显示，否则显示并提示"未检测到私钥"）
   - 或注册全局快捷键 `Ctrl+Shift+L`（`globalShortcut.register`），仅私钥存在时响应

4. **窗口**：复用现有界面，`BrowserWindow` 加载 `dist/license-admin.html`，preload 用 `electron/license-admin-preload.js`（需一并迁移到 `electron/`）。

5. **可见性控制**：未检测到私钥时隐藏菜单项与快捷键响应，避免普通用户困惑。

**权衡**

| 项 | 说明 |
|---|---|
| 优点 | 作者日常最顺手，打开桌宠即可签发 |
| 代价 | 签发 UI 与逻辑进入用户安装包（体积增加很小） |
| 风险 | 若他人设法放入自己的私钥即可签发——但公钥在应用内是固定的，伪造码仍无效；真正前提是**你的私钥不能外泄** |

---

### 10.3 选择建议

| 场景 | 建议 |
|---|---|
| 只在本开发机签发 | 当前 bat 方案足够 |
| 需要在多台电脑 / 无 Node 环境签发 | 方案 B（独立 EXE） |
| 想要"打开桌宠就能签发" | 方案 C（集成进主程序） |
